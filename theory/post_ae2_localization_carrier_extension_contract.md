Status:
`ACCEPTANCE_CONTRACT_DEFINED__EXTENSION_NOT_AUTHORIZED_OR_INSTANTIATED`.

The unchanged-AE2 carrier kill screen is complete at its audited evidence
boundary.  This document specifies what a future action version would have to
contain and prove before it could supply the missing physical-localization
bridge.  It does not select a candidate, name a new action version, add an
equation or coefficient, or authorize implementation.

## Minimum carrier

A candidate must introduce an action-owned map

```text
D_A : z -> (D_enc, Sigma_enc, X, n, K, ...)
```

or a covariant localization scalar such that

```text
Sigma_enc = {x : chi_A[Phi](x)=0},
d chi_A restricted to Sigma_enc != 0.
```

Equivalent domain formulations are admissible if they prove the same
well-posed embedded-interface data.  In either form, variation of the same
extended action must derive the interface and junction equations.  A manual
choice of enclosure route is not an action selection.

## Required proof chain

Before promotion, a proposed extension must pass all twelve `LEC` gates in the
machine-readable contract.  They require explicit owner authorization and
versioning, covariant carrier definition, regularity, same-action interface
variation, route selection, transport of the action dependency closure,
preservation of the AE2 reset and family-projector intertwiner, actual C2
family/mode instantiation, child inheritance, reduction to AE2 away from the
localized support, non-fitted provenance for every new coefficient, and no
change to frozen particle assets.

The transported field set for a BHSM state `B_i` is

```text
Dep_A(B_i) = TC(
  fields defining B_i,
  fields required by M_SM(B_i),
  fields entering delta S on Sigma_enc
).
```

This is the closure the physical enclosure must carry.  It is more precise
than requiring every field everywhere.

The contract is therefore executable preparation for an owner decision, not
the decision itself.  `FULL_BHSM_COMPLETE = FALSE`.
