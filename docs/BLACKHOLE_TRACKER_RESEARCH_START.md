software checks do not assert journal submission, external peer review or
acceptance. Bundled demonstrations and the exhibit animation are synthetic.
The separate real-observation pilot processed all 100 historical OGLE-III
events/76,344 native measurements: 89 baseline model/noise screens were
inadequate, 11 passed chi-square and two met stricter archival follow-up
criteria. All masses remain unresolved and no new black-hole interpretation
is established. All three declared models in the separate 2023 joint benchmark
fail adequacy, so no reliable known-system mass is accepted by this campaign.
Its published black-hole classification remains independent literature evidence.
The new synthetic study processes 4,608 datasets and 4,736 fits but fails three
photometric uncertainty-calibration tests. A separately frozen Student
known-system experiment also retains unresolved numerical starts and no accepted
mass. Those findings keep the scientific hold explicit; matching a published
conditional point is insufficient for recovery.

## Candidate selection and localization

Open **Primary target** in the installed app for the source-pinned program.
Previously published **Gaia18ajz** is the provisional lead for independent
evaluation. All eight published model/prior/near--far alternatives are visible;
their branch weights are not black-hole probabilities. The known OB110462
benchmark and a published brown-dwarf comparison provide separate references.
Native candidate adequacy and independent known-black-hole recovery remain
unaccepted, so scientific publication is held. Read the
[primary-target guide](../products/blackhole_tracker/research/primary_target_20261023/README.md)
to verify or explicitly refetch the exact public context bytes. Context intake
does not admit a source association or a candidate likelihood.

The separate **Evidence spectrum** retains 1,808 model records, all modes and
failures; these are not 1,808 unique objects. Search qualified catalog aliases,
collect source-event context, export JSON or CSV, clear the view and replay.
Hidden selected cases are retained. The **Moving lens** workspace and
[sixth notebook](../products/blackhole_tracker/notebooks/06_moving_lens_and_primary_target.ipynb)
provide an explicit synthetic fit/export/replay walkthrough. Actual inputs need
measured lens angular positions, native epochs, calibration, supplied covariance
and association evidence; no record in the frozen spectrum supplies an admitted
lens track. Angular motion alone identifies neither mass nor a black hole.

Supported gravitational geometry is interpreted as BHSM surface topography,
with the same exterior optical response counted once. A conditional fitted
curve alone does not validate its gravitational origin or identify its source.
The later [author clarification](BHSM_TRACKER_ENVELOPMENT_SEARCH_CLARIFICATION_20261023.md)
defines the **BHSM envelope-boundary differential** and makes distinguishing
different envelopments the organizing question. This usage is distinct from
conventional rotational frame dragging. The paper explains a conditional
compact-versus-extended bending-profile diagnostic; it does not add a
dark-matter classifier, a measured spin or a global hypersphere radius.

The [candidate atlas guide](../products/blackhole_tracker/CANDIDATE_ATLAS.md) and [portable metadata rebuild](../papers/bhsm_blackhole_tracker_20261021/candidate_atlas_20261023/README_INVENTORY_v3.txt) retain 155 source/event directions: 100 pilot + 59 parallax - 4 verified shared identities. Three investigation targets have different qualifications; no new black-hole interpretation is established. The separate published benchmark is a literature label, with independent engine recovery unresolved. No present-day lens position, mass, distance or absolute motion is supplied by this inventory.

Launch `Start_Blackhole_Tracker_Atlas.cmd` or `blackhole-tracker serve --open --page atlas`. Filter the view, export JSON, reset and open the replay. All 155 cohort records and the separate benchmark are preserved. CLI users can run `blackhole-tracker atlas export --tier BLACK_HOLE_SEARCH_TARGET --output targets.json`, then `blackhole-tracker atlas replay targets.json --output restored-targets`; output paths must be new. SHA-256 checks consistency, not scientific acceptance.

## A first complete run

Use Python 3.11 or newer; the dedicated product CI uses Python 3.12 on Linux
and Windows. For direct app access, the
[Museum exhibit](https://ncarberry64.github.io/Berger-Hopf-Standard-Model/#blackhole-tracker)
provides the exact reviewed product ZIP and wheel with research-license notices.
Extract the product ZIP completely; its app directory is `product/`, where
Windows users can double-click `Start_Blackhole_Tracker.cmd`. The environment
installation commands below also apply from that directory on other platforms.
For the complete paper/reviewer source, obtain the portable source archive
from a completed run of the
[Formal Blackhole Tracker workflow](https://github.com/ncarberry64/Berger-Hopf-Standard-Model/actions/workflows/blackhole-tracker.yml).
Select a run and revision explicitly, rather than treating any latest run as
the manuscript's reviewed release. The `blackhole-tracker-paper-and-source`
artifact includes the product, three paper directories, verification helpers
and license notices. A complete BHSM clone is optional.

From the root of that archive or this checkout:

```text
cd products/blackhole_tracker
python -m venv .venv
```

Install and launch using the environment's interpreter. PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe -m bhtracker serve --open
```

Linux/macOS:

```bash
.venv/bin/python -m pip install .
.venv/bin/python -m bhtracker serve --open
```

Windows users can instead double-click
[`Start_Blackhole_Tracker.cmd`](../products/blackhole_tracker/Start_Blackhole_Tracker.cmd)
in the product directory. The default app address is
`http://127.0.0.1:8765/`; add `--port 8766` if the port is occupied. The Museum
explains the workflow and provides access instructions; inference runs in the
locally installed application. Dependency installation uses the configured
package index. Fitting needs no remote account or API key.

1. Load **Nearby compact-mass track** (CLI example `nearby_motion`), select **Validate dataset**, then **Run fit** with
   **Ordinary lens response**.
2. Read the status, mass, reference center, observer proper motion, uncertainties
   and residuals. Open the BHSM interpretation to see which quantities are
   fitted, derived at a declared radius or proposed.
3. Select **Download replay bundle** and retain that ZIP with the wheel/revision
   used. It includes input, full covariance, fit controls, result and provenance.
4. Replay the downloaded ZIP in a fresh output directory, using the same
   installed interpreter. Replace the example filename with the actual download:

```text
python -m bhtracker replay /path/to/bhsm-analysis-replay.zip --output /path/to/fresh/replayed
```

Here and below, `python` means the installed environment interpreter shown
above. Inspect `replayed/replay_check.json` for prediction differences and
software/interpretation comparisons. Older exports can retain matching
predictions while recording an explicit interpretation-version change.

For a browser-free round trip, run from the product directory with that same
interpreter:

```text
python -m bhtracker example nearby_motion --output user_runs/nearby.json
python -m bhtracker validate user_runs/nearby.json
python -m bhtracker fit user_runs/nearby.json --family gr --nuisance shear --starts 3 --output user_runs/fit
python -m bhtracker replay user_runs/fit --output user_runs/replayed
```

Use fresh output directories. The CLI name `gr` selects the ordinary optical
family with its explicit BHSM interpretation. For the Python API, complete
CSV/full-covariance contract, negative statuses and conditional `r1` mode, use
the [product guide](../products/blackhole_tracker/README.md). The executed
notebooks are [mass and motion](../products/blackhole_tracker/notebooks/01_compact_mass_and_motion.ipynb)
and [conditional boundary response](../products/blackhole_tracker/notebooks/02_conditional_boundary_response.ipynb).
Their replay dependencies and interpreter selection are described in the
[paper reproduction guide](../papers/bhsm_blackhole_tracker_20261021/README.md#reproduce-the-separate-calculations).
Full historical calibration is a separate reproduction task, not a first-run
installation requirement.

## A complete run on native unresolved photometry

Open **Unresolved photometry** in the local app, or append `/photometry` to its
loopback URL. Import an actual optimized OGLE-III `.dat` file or the explicitly
versioned 2022 benchmark files. The native route retains source-row identities,
raw hashes, magnitude errors, timing and calibration; it creates no image
positions, image flux ratio, time delay, distances or supplied full covariance.
Validate, fit, inspect model adequacy and residuals, then export and replay the
native ZIP with the same `replay` command above. A converged photometric fit
does not by itself validate a gravitational origin or measure mass. Its
conditional timescale and blending constraints can guide further investigation.
The separate [native observation contract](../products/blackhole_tracker/UNRESOLVED_OBSERVATIONS.md)
documents the likelihood and the missing-metadata gates for precision astrometry.

```text
python -m bhtracker import-ogle3 /path/to/photBLG122.6.I.83113.dat --output observations.json
python -m bhtracker fit-photometry observations.json --output native_fit
python -m bhtracker replay native_fit --output native_replayed
```

The third executed [native-photometry notebook](../products/blackhole_tracker/notebooks/03_native_unresolved_photometry.ipynb)
uses external authentic observations when `BHSM_DATA_ROOT` is supplied; its
portable fallback is clearly synthetic. The frozen pilot record includes all
100 cases, diagnostics, residual plots, prior aliases, the benchmark limitations
and a wrapper for exact isolated reproduction. The historical benchmark's HST
time/frame metadata remain unresolved; no guessed precision joint mass is used.

## What the BHSM result does and does not establish

The [23 October author clarification](BHSM_AUTHOR_SURFACE_GEOMETRY_CLARIFICATION_20261023.md)
includes gravitational topography itself in BHSM surface deformation, within a
common frame across scales. When observations support a gravitational origin,
the reconstructed exterior is interpreted as that surface geometry; no non-GR
anomaly is required. Locating and characterizing configurations is useful
before a unique object type is established. A conditional light-curve fit
alone does not validate that origin or identify a black hole.

The adopted Einstein/GHY sector describes one compact exterior. Ordinary
mass, center and motion, when identified, fit that same configuration; its
spherical boundary representation counts the same gravitational potential once. A supplied
enclosing radius is not an observed hard surface. The optional R1 calculation
has separate source/metric matching and admission assumptions. A supported
track is evidence for the admitted optical model, not a unique microscopic
BHSM state, a horizon detection or an already discovered new black hole.
Rejected, partly constrained and unresolved results remain scientific outputs.

The [boundary dictionary](../papers/bhsm_blackhole_tracker_20261021/provenance/bhsm_boundary_mass_interpretation.md)
and [hashed source ledger](../papers/bhsm_blackhole_tracker_20261021/provenance/bhsm_boundary_mass_interpretation_sources.json)
connect those interpretations to recovered BHSM sources. The
[22 October core/surface amendment](BHSM_NORMAN_CORE_SURFACE_AMENDMENT_20261022.md)
separates abstract, nonspacetime core data from spacetime-side surface dynamics;
its [claim ledger](../artifacts/current_semantics/BHSM_NORMAN_CORE_SURFACE_AMENDMENT_20261022.json)
records remaining matching and terminal-transfer requirements. No measured
core parameter or terminal rate is supplied by the tracker.

For the broader program, read [claim boundaries](../CLAIMS.md),
